# 🗄️ Database Schema — Immersive Villager AI

## Overview

This document defines the complete PostgreSQL schema for the Immersive Villager AI system, including support for **dual AI modes** (MONOLITHIC and MICROSERVICES) and **structure learning**.

---

## Core Tables (MVP - Phase 0/1)

### 1. villagers

Central registry for all AI villagers.

```sql
CREATE TABLE villagers (
  villager_id TEXT PRIMARY KEY,
  name TEXT,
  home_x REAL NOT NULL,
  home_y REAL NOT NULL,
  home_z REAL NOT NULL,
  profession TEXT,
  created_at BIGINT NOT NULL,
  last_seen BIGINT,
  is_active BOOLEAN DEFAULT TRUE
);

CREATE INDEX idx_villagers_active ON villagers(is_active) WHERE is_active = TRUE;
```

**Design Notes:**
- `villager_id` is the Minecraft entity ID (immutable)
- `home_x/y/z` defines the villager's territorial center (used for proximity calculations)
- `is_active` flags villagers that are currently loaded in-world

---

### 2. concepts

Shared knowledge pool of semantic concepts (events, items, structures).

```sql
CREATE TABLE concepts (
  concept_id SERIAL PRIMARY KEY,
  name TEXT NOT NULL UNIQUE,
  semantic_vector_manual VECTOR(5),      -- [C, V, I, S, X] for MONOLITHIC mode
  semantic_vector_minilm VECTOR(384),    -- MiniLM embedding for MICROSERVICES mode
  discovery_count INTEGER DEFAULT 0,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_concepts_vector_manual ON concepts USING ivfflat (semantic_vector_manual vector_cosine_ops);
CREATE INDEX idx_concepts_vector_minilm ON concepts USING ivfflat (semantic_vector_minilm vector_cosine_ops);
```

**Design Notes:**
- **Dual Vector Support:** Both `semantic_vector_manual` (5D) and `semantic_vector_minilm` (384D) stored to support AI_MODE toggle without schema changes
- `discovery_count` tracks how many villagers have learned this concept
- Only one vector will be used at runtime based on AI_MODE config

---

### 3. villager_discoveries

Tracks which concepts each villager has learned (enforces subjectivity).

```sql
CREATE TABLE villager_discoveries (
  villager_id TEXT REFERENCES villagers(villager_id) ON DELETE CASCADE,
  concept_id INTEGER REFERENCES concepts(concept_id) ON DELETE CASCADE,
  discovered_at BIGINT NOT NULL,
  discovery_method TEXT,  -- 'witnessed', 'gossip', 'taught', 'built'
  PRIMARY KEY (villager_id, concept_id)
);

CREATE INDEX idx_discoveries_villager ON villager_discoveries(villager_id);
CREATE INDEX idx_discoveries_concept ON villager_discoveries(concept_id);
```

**Design Notes:**
- Ensures villagers only access concepts they've personally learned
- `discovery_method` tracks how knowledge was acquired (for social reasoning)

---

### 4. episodes

Recorded memories of player interactions.

```sql
CREATE TABLE episodes (
  id SERIAL PRIMARY KEY,
  villager_id TEXT NOT NULL REFERENCES villagers(villager_id) ON DELETE CASCADE,
  actor_id TEXT NOT NULL,
  semantic_vector_manual VECTOR(5),      -- [C, V, I, S, X] for MONOLITHIC mode
  semantic_vector_minilm VECTOR(384),    -- MiniLM embedding for MICROSERVICES mode
  summary_text TEXT,                     -- T5-small generated summary (MICROSERVICES mode)
  duration INTEGER,
  event_count INTEGER,
  seal_reason TEXT,
  timestamp BIGINT NOT NULL
);

CREATE INDEX idx_episodes_villager ON episodes(villager_id, timestamp DESC);
CREATE INDEX idx_episodes_actor ON episodes(actor_id, timestamp DESC);
CREATE INDEX idx_episodes_vector_manual ON episodes USING ivfflat (semantic_vector_manual vector_cosine_ops);
CREATE INDEX idx_episodes_vector_minilm ON episodes USING ivfflat (semantic_vector_minilm vector_cosine_ops);
```

**Design Notes:**
- **Dual Vector Support:** Episodes store both 5D manual vectors and 384D MiniLM embeddings
- `summary_text` added for MICROSERVICES mode (generated by T5-small model)
- Vector indexes enable fast semantic similarity search

---

### 5. relationships

Tracks trust scores and interaction counts per player.

```sql
CREATE TABLE relationships (
  id SERIAL PRIMARY KEY,
  villager_id TEXT NOT NULL REFERENCES villagers(villager_id) ON DELETE CASCADE,
  actor_id TEXT NOT NULL,
  interaction_count INTEGER DEFAULT 0,
  trust_score REAL DEFAULT 0.5,
  last_interaction BIGINT,
  UNIQUE(villager_id, actor_id)
);

CREATE INDEX idx_relationships_villager ON relationships(villager_id);
CREATE INDEX idx_relationships_actor ON relationships(actor_id);
```

**Design Notes:**
- `trust_score` ranges from 0.0 (hostile) to 1.0 (trusted)
- Initialized at 0.5 (neutral) on first interaction

---

### 6. working_memory

Snapshot of villager's current mental state (synced from DynamicProperties).

```sql
CREATE TABLE working_memory (
  villager_id TEXT PRIMARY KEY REFERENCES villagers(villager_id) ON DELETE CASCADE,
  current_mood_manual VECTOR(5),         -- [C, V, I, S, X] for MONOLITHIC mode
  current_mood_minilm VECTOR(384),       -- MiniLM embedding for MICROSERVICES mode
  current_focus TEXT,
  shock_state BOOLEAN DEFAULT FALSE,
  last_update BIGINT NOT NULL
);
```

**Design Notes:**
- **Dual Vector Support:** Current mood stored in both formats
- Synced from DynamicProperties every 5 seconds (debounced)

## Structure System Tables (Post-MVP)

### 7. structure_templates

Stores "recipes" for building segments (e.g., wall segment, floor pattern).

```sql
CREATE TABLE structure_templates (
  id SERIAL PRIMARY KEY,
  label TEXT NOT NULL,                   -- e.g., 'oak_wall_segment', 'cobblestone_floor_5x5'
  pattern_hash TEXT UNIQUE,              -- Spatial hash for MONOLITHIC mode (fast deduplication)
  embedding VECTOR(384),                 -- MiniLM vector for MICROSERVICES mode (semantic search)
  instructions JSONB NOT NULL,           -- Relative block positions: [{"x":0,"y":1,"z":0,"type":"oak_plank"}]
  dimensions JSONB,                      -- {"width": 3, "height": 5, "depth": 1}
  created_by TEXT,                       -- villager_id or player_id who first created this
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  observation_count INTEGER DEFAULT 1    -- How many times this pattern has been seen
);

CREATE INDEX idx_templates_hash ON structure_templates(pattern_hash);
CREATE INDEX idx_templates_embedding ON structure_templates USING ivfflat (embedding vector_cosine_ops);
CREATE INDEX idx_templates_label ON structure_templates(label);
```

**Design Notes:**
- **Hybrid Recognition:** Uses `pattern_hash` for exact matches (MONOLITHIC) and `embedding` for semantic similarity (MICROSERVICES)
- `instructions` stores relative block coordinates from anchor point
- `observation_count` tracks pattern frequency (for learning reinforcement)

---

### 8. structure_blueprints

High-level assembly guides for complete buildings.

```sql
CREATE TABLE structure_blueprints (
  id SERIAL PRIMARY KEY,
  name TEXT NOT NULL,                    -- e.g., 'Steve's Cozy Cottage', 'Blacksmith Workshop'
  embedding VECTOR(384),                 -- Semantic "vibe" of the whole structure
  composition JSONB NOT NULL,            -- List of template IDs and their relative offsets
  tags JSONB,                            -- ['residential', 'wood', 'small', 'has_bed']
  functional_zones JSONB,                -- {"resting": {...}, "utility": {...}, "entry": {...}}
  created_by TEXT,                       -- villager_id or player_id
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  build_count INTEGER DEFAULT 0          -- How many times this blueprint has been used
);

CREATE INDEX idx_blueprints_embedding ON structure_blueprints USING ivfflat (embedding vector_cosine_ops);
CREATE INDEX idx_blueprints_tags ON structure_blueprints USING gin(tags);
CREATE INDEX idx_blueprints_name ON structure_blueprints(name);
```

**Design Notes:**
- `composition` references `structure_templates` IDs with spatial offsets
- `functional_zones` stores semantic zones (resting area, utility area, entry/exit)
- `tags` enables fast filtering (e.g., "find all residential buildings")

---

### 9. villager_world_map

Villager's subjective map of observed structures in the world.

```sql
CREATE TABLE villager_world_map (
  id SERIAL PRIMARY KEY,
  villager_id TEXT NOT NULL REFERENCES villagers(villager_id) ON DELETE CASCADE,
  structure_id INTEGER REFERENCES structure_blueprints(id) ON DELETE CASCADE,
  anchor_x INT NOT NULL,
  anchor_y INT NOT NULL,
  anchor_z INT NOT NULL,
  confidence REAL DEFAULT 1.0,           -- How sure the villager is (0.0-1.0)
  last_observed BIGINT NOT NULL,
  dimension TEXT DEFAULT 'overworld',
  UNIQUE(villager_id, anchor_x, anchor_y, anchor_z)
);

CREATE INDEX idx_world_map_villager ON villager_world_map(villager_id);
CREATE INDEX idx_world_map_location ON villager_world_map(anchor_x, anchor_y, anchor_z);
CREATE INDEX idx_world_map_structure ON villager_world_map(structure_id);
```

**Design Notes:**
- **Subjective Positioning:** Each villager maintains their own world map (no shared spatial database)
- `confidence` decreases over time if structure is modified or not re-observed
- `anchor_x/y/z` is the (0,0,0) reference point for the structure instance

### 10. build_tasks

Active building tasks for villagers (work queue).

```sql
CREATE TABLE build_tasks (
  id SERIAL PRIMARY KEY,
  villager_id TEXT NOT NULL REFERENCES villagers(villager_id) ON DELETE CASCADE,
  blueprint_id INTEGER REFERENCES structure_blueprints(id),
  template_id INTEGER REFERENCES structure_templates(id),
  anchor_x INT NOT NULL,
  anchor_y INT NOT NULL,
  anchor_z INT NOT NULL,
  status TEXT DEFAULT 'pending',         -- 'pending', 'in_progress', 'completed', 'failed'
  current_step INTEGER DEFAULT 0,        -- Index of current block in instructions
  total_steps INTEGER NOT NULL,
  trigger_source TEXT,                   -- 'player_command', 'autonomous_need', 'gossip'
  trigger_data JSONB,                    -- Additional context (e.g., NER-extracted blueprint)
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  started_at BIGINT,
  completed_at BIGINT
);

CREATE INDEX idx_build_tasks_villager ON build_tasks(villager_id, status);
CREATE INDEX idx_build_tasks_status ON build_tasks(status);
```

**Design Notes:**
- **Per-Block Tracking:** `current_step` allows villagers to resume interrupted builds
- `trigger_source` distinguishes player commands from autonomous decisions
- `trigger_data` stores NER-extracted information (e.g., block type, size)

### 11. pattern_observations

Real-time tracking of repeated patterns during player building (for learning).

```sql
CREATE TABLE pattern_observations (
  id SERIAL PRIMARY KEY,
  villager_id TEXT NOT NULL REFERENCES villagers(villager_id) ON DELETE CASCADE,
  pattern_hash TEXT NOT NULL,            -- Spatial hash of observed pattern
  block_sequence JSONB NOT NULL,         -- Ordered list of block placements
  observation_timestamp BIGINT NOT NULL,
  consolidated BOOLEAN DEFAULT FALSE     -- True if converted to structure_template
);

CREATE INDEX idx_pattern_observations_villager ON pattern_observations(villager_id, consolidated);
CREATE INDEX idx_pattern_observations_hash ON pattern_observations(pattern_hash);
```

**Design Notes:**
- **Real-Time Learning:** Stores sequential block placements as villager observes
- `consolidated` flag prevents duplicate template creation
- Garbage-collected after 24 hours or when converted to template

## Caching Strategy (Deduplication)

Both AI modes avoid redundant inference by checking **existing tables** before running models:

### MONOLITHIC Mode Caching

1. **Structure Recognition:** Check `structure_templates` by `pattern_hash` (instant lookup)
2. **Concept Matching:** Check `concepts` by vector similarity (1-5ms)
3. **Episode Matching:** Check recent `episodes` by vector similarity (1-5ms)

### MICROSERVICES Mode Caching

1. **Structure Recognition:** Check `structure_templates` by embedding similarity (1-5ms)
2. **Event Descriptions:** Query `episodes` table with `summary_text` LIKE pattern (2-10ms)
3. **Concept Vectors:** Check `concepts` by embedding similarity (1-5ms)

**Implementation Example:**

```javascript
/**
 * Generate embedding with automatic caching via concepts table.
 * @param {string} text - Text to vectorize
 * @returns {Promise<number[]>} 384D embedding
 */
async function generateEmbeddingWithCache(text) {
  // Check if this exact text exists in concepts table
  const cached = await pool.query(
    'SELECT semantic_vector_minilm FROM concepts WHERE name = $1',
    [text]
  );
  
  if (cached.rows.length > 0) {
    return JSON.parse(cached.rows[0].semantic_vector_minilm);
  }
  
  // Not cached: Generate new embedding
  const embedding = await embedder(text, { pooling: 'mean', normalize: true });
  return Array.from(embedding.data);
}
```

**Why No Separate Cache Table:**
- Existing tables (`concepts`, `episodes`, `structure_templates`) already store embeddings
- Reduces table count and schema complexity
- Leverages vector similarity indexes for fuzzy matching
- Natural data lifecycle (cache pruning = deleting old episodes)

## Schema Migration: MONOLITHIC → MICROSERVICES

When toggling between AI modes, **no schema changes required**. Both vector columns coexist:

```sql
-- Example: Querying episodes in MONOLITHIC mode
SELECT * FROM episodes 
ORDER BY semantic_vector_manual <=> '[0.8,0.9,0.3,0.7,0.1]'::vector 
LIMIT 5;

-- Example: Querying episodes in MICROSERVICES mode
SELECT * FROM episodes 
ORDER BY semantic_vector_minilm <=> $1::vector(384) 
LIMIT 5;
```

**Backend Logic:**

```javascript
const AI_MODE = process.env.AI_MODE || 'MONOLITHIC';

function queryEpisodesBySimilarity(vectorData) {
  if (AI_MODE === 'MONOLITHIC') {
    const vectorString = `[${vectorData.C},${vectorData.V},${vectorData.I},${vectorData.S},${vectorData.X}]`;
    return pool.query(
      'SELECT * FROM episodes ORDER BY semantic_vector_manual <=> $1::vector LIMIT 10',
      [vectorString]
    );
  } else {
    return pool.query(
      'SELECT * FROM episodes ORDER BY semantic_vector_minilm <=> $1::vector(384) LIMIT 10',
      [vectorData.embedding]
    );
  }
}
```

### Example 3: Structure Template Creation (Hybrid Learning)

```javascript
// Real-time: Player builds a wall
const blockSequence = [
  { x: 0, y: 0, z: 0, type: 'oak_plank', timestamp: 1000 },
  { x: 0, y: 1, z: 0, type: 'oak_plank', timestamp: 1200 },
  { x: 0, y: 2, z: 0, type: 'oak_plank', timestamp: 1400 }
];

// Step 1: Generate spatial hash (MONOLITHIC)
const patternHash = generateSpatialHash(blockSequence);  // "oak_plank:0:0:0|oak_plank:0:1:0|oak_plank:0:2:0"

// Step 2: Check if template exists
const existing = await pool.query(
  'SELECT id FROM structure_templates WHERE pattern_hash = $1',
  [patternHash]
);

  // Already learned, increment observation count
  await pool.query(
    'UPDATE structure_templates SET observation_count = observation_count + 1 WHERE pattern_hash = $1',
    [patternHash]
  );
} else {
  // New pattern: Generate MiniLM embedding (MICROSERVICES)
  const description = 'A vertical pillar of 3 oak planks';
  const embedding = await generateEmbedding(description);  // 384D vector
  
  // Save as new template
  await pool.query(
    'INSERT INTO structure_templates (label, pattern_hash, embedding, instructions, dimensions, created_by) VALUES ($1, $2, $3, $4, $5, $6)',
    ['oak_wall_segment', patternHash, `[${embedding.join(',')}]`, JSON.stringify(blockSequence), JSON.stringify({width: 1, height: 3, depth: 1}), villagerID]
  );
}

## Performance Considerations

### Index Strategy

**Vector Indexes (ivfflat):**
- **Build Time:** 10-30 seconds for 10,000 rows
- **Query Time:** 1-5ms (approximate nearest neighbor)
- **Accuracy:** 99%+ recall for top-10 results
- **Update Frequency:** Rebuild every 1,000 new rows

**JSONB Indexes (GIN):**
- **Use Case:** Fast filtering by tags (`WHERE tags @> '["residential"]'`)
- **Build Time:** 5-10 seconds for 10,000 rows
- **Query Time:** 2-10ms

**Composite Indexes:**
- `(villager_id, timestamp DESC)` enables fast "recent episodes" queries
- `(villager_id, status)` enables fast build task filtering

---

### Storage Estimates

**Per Villager (100 episodes, 10 learned concepts, 5 observed structures):**
- Episodes: ~15KB (5D vectors) or ~60KB (384D vectors + summaries)
- Discovered Concepts: ~500 bytes (5D) or ~2KB (384D)
- World Map (observed structures): ~1KB
- Relationships: ~100 bytes
- Build Tasks: ~500 bytes
- **Total:** ~17-64KB per villager

**50 Villagers:**
- MONOLITHIC mode: ~1-1.5MB
- MICROSERVICES mode: ~3-3.5MB

**Storage Growth:**
- Episodes: ~1MB per 10,000 episodes (MONOLITHIC) or ~4MB (MICROSERVICES)
- Structure templates: ~100KB per 1,000 templates

-- Rebuild vector indexes weekly (or after 10,000 new rows)
REINDEX INDEX idx_concepts_vector_manual;
REINDEX INDEX idx_concepts_vector_minilm;
REINDEX INDEX idx_episodes_vector_manual;
REINDEX INDEX idx_episodes_vector_minilm;
```

### Data Retention Policy

```sql
-- Archive old episodes (older than 30 days)
DELETE FROM episodes WHERE timestamp < (EXTRACT(EPOCH FROM NOW()) * 1000) - (30 * 24 * 60 * 60 * 1000);

-- Clean up consolidated pattern observations
DELETE FROM pattern_observations WHERE consolidated = TRUE AND observation_timestamp < (EXTRACT(EPOCH FROM NOW()) * 1000) - (24 * 60 * 60 * 1000);
```
